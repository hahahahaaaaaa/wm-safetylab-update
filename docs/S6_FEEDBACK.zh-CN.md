# S6 反馈与更新：第一版

保持原版八步向导，只在 S6 插件卡片内增加配置。S6 包括残差校准监控、CUSUM 告警/接管、在线玩具反馈投毒；不训练真实模型，不实现尚未接通的 `on_update`。

## 预设残差

定义版本 `planned-next-rms/v1`：

```text
r[t] = sqrt(mean(((predicted_next - embed(next_obs)) / scale)^2))
z[t] = (r[t] - center) / spread
g[t] = max(0, g[t-1] + z[t] - drift)
g[t] >= threshold 时告警
```

`scale` 默认1，可通过高级JSON提供与潜状态展平维度相同的正尺度向量。`center`、`spread`、`threshold` 应在对应模型和环境的独立干净种子上校准；不同表示空间的数值不能直接比较。默认参数只是可编辑起点，不是已验证安全阈值。

预测对应模型原计划动作；默认排除实际命令改变的步骤。开启 `include_changed` 后，解释为原计划与实际执行结果的闭环偏离，不能将其等同于模型自身预测误差。接管步骤始终排除，避免自身备用控制造成反复告警。不可用样本及冷却期间会清空累计量，均显式记录，不把缺失值当正常误差。

本版检测器在 `after_step` 中读取原始环境反馈和模型探针，不读取仿真真值；它与学习器收到的投毒反馈分开。因此不能把它宣称为通用反馈投毒检测器。每个有效残差记录预测向量、下一观测编码、尺度与数值，支持独立重算。

## 插件

| ID | 作用 |
|---|---|
| `s6-residual-monitor` | 只读记录残差和有效性，用于校准，不改变动作和学习反馈 |
| `s6-cusum` | 累积异常证据，支持 `none`（只告警）、`stop`（下一步结束回合）、`fallback`（备用动作） |
| `s6-feedback-poison` | 仅限 `toy-planner-online`＋ToyPick，按 factor 缩小提供给学习器的位置增量 |

CUSUM 告警发生在第 t 步执行后，最早第 t+1 步接管。备用模式必须提供适合控制器的 `fallback_action`，或由环境明确提供 `safe_action`，不自动把全零动作称为安全动作。冷却步数至少为备用接管步数。告警后重置累计量，进入冷却；每回合重置检测状态。

与 S5 共用原有接管机制，优先级明确为：任何停止请求优先；否则 S5 直接备用动作优先于 S6 待执行备用请求。被 S5 暂时覆盖的 S6 备用请求保留剩余执行步数，不能未执行就消耗。若回合已结束，最后一步产生的告警不会凭空产生下一步接管。

反馈投毒 `factor` 范围0..1，1为无投毒；支持 start/end。只修改学习器收到的 `next_obs`，真实环境状态和原始观测保留。记录原始位置、投毒位置、报告位移。验收观察在线玩具的动作增益估计变化，不能称为 TD-MPC2 权重投毒。

## 校准、试验与重算

```bash
./dev.sh toy-python scripts/s6_acceptance.py cpu --output .workspace/results/新的S6目录
./dev.sh toy-python scripts/s6_acceptance.py gpu --output .workspace/results/同一S6目录
./dev.sh toy-python -m wms.episodes.s6_metrics /path/to/run/output --anomaly-start 8
```

当前验收采用逐维尺度：从干净预测误差计算每个维度的 RMS，尺度下限0.001，避免夹持状态等跳变维度掩盖位置变化。所有尺度只由干净校准集决定。初版统一尺度的记录保留，不覆盖原结果。

CPU：干净校准 seeds600–619，评估 seeds700–719，每组20回合。受控变化仅使用验收脚本中的隐藏执行增益改变（第8步开始）；开始时刻仅供评价，不输入检测器。另测告警、停止、显式玩具备用动作，以及在线学习干净/投毒/零投毒对照。

GPU：使用已有冻结 TD-MPC2 checkpoint，独立重建每回合场景。校准 seeds1400–1419，评估 seeds1500–1519。故障为第10–39步的显式限幅动作噪声，启用 include_changed，评价闭环偏离而非模型失效。投毒不在 GPU 模型上验收。

校准以干净残差均值/标准差为标准化参数，阈值为干净序列峰值CUSUM的1.2倍加0.5，至少为1；仅使用校准种子，不根据评估结果反复调整。该经验规则不构成误报率保证，误报率必须在独立评估中报告。

`s6_metrics` 独立重算向量RMS和累计量，核对告警记录与接管来源，复用 S5 的成功/危险/接管核对。报告正常回合告警率、异常前告警率、可观察异常回合检测率和检测延迟；没有有效异常后样本时报告不可观察，不伪报为零漏报。

生成综合报告：`./dev.sh toy-python scripts/s6_acceptance_report.py 新验收目录 --initial 初版验收目录`。它把已完成的CPU检测、在线投毒、GPU检测分组登记到原版结果页，不额外运行模型。综合验收结果见 `docs/S6_ACCEPTANCE_20261030.zh-CN.md`；程序核对通过不代表检测效果已达标，GPU未检出的结果也必须保留。

本版还修复严格模式把原本不变的NaN误认为原地修改的问题；NaN仍被残差有效性检查排除。停止回合中“记录步数”包括未执行的停止请求，“执行步数”不包括它，重算分别保存。
