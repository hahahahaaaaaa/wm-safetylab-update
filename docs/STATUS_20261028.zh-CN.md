## 1. WM-SafetyLab 代码框架

版本 0.3.0。一次实验从配方出发，经队列进独立 Python 进程，结果落到 `runs/<id>/`。

```text
Web / CLI / Python
        │
        ▼
HTTP API（src/wms/app）
        │
配方注册表 native/*/recipes.json ──► 队列 + SQLite（src/wms/core）
        │
        ▼
src/wms/runners/unified.py
   ├─ 入口 A  native：原样调用论文训练 / 评测
   └─ 入口 B  episodes/kernel.py：平台逐步驱动闭环，插件挂在 ENV、S1–S6
        │
        ▼
result.json、episodes、steps.jsonl、trace.jsonl、视频
        │
独立评价 → 同种子配对比较（scripts/compare_runs.py）
```

闭环六个环节：

```text
观测 → S1 感知 → S2 状态/记忆 → S3 预测 → S4 规划 → S5 动作 → 仿真
                                                              │
                         S6 反馈（obs, action, next_obs, reward）◄┘
环境本身的改动走 ENV，不占用 S1–S6。
```

插件四种角色：`fault`（须有强度 0 的 neutral）、`attack`（须带威胁卡）、`defense`（默认不能读仿真真值）、`monitor`（只读，平台会检查）。S2–S4 依赖模型探针；S1、S5 任何模型都能挂。

红队工作台在这套内核之上编排实验，不另写一套执行器：

- 后端：`src/wms/redteam/`、`src/wms/app/redteam_api.py`，前缀 `/api/v1`
- 前端：`web/src/pages/` 的新建实验、配置、进度、结果四页，标题是“具身仿真红队测试”

模型适配器同构：`engines/<模型>/native.py` 走论文代码，`adapter.py` 接回合内核。真正要精读的是 TD-MPC2（探针齐全）和 MemoryVLA（记忆读写）。其余引擎看 `probes` 声明即可。

## 2. WM-SafetyLab 做到哪里

**底座已经能承载实验。** 入口 A 证明“和论文流程一致”，入口 B 证明“平台逐步驱动且不改变动作”。TD-MPC2 × PushCube、MemoryVLA × SimplerEnv-Bridge 两条入口的逐步动作差为 0。玩具环境上的插件一致性测试（`wms plugin test`）可用。

| 已在代码里 | 边界 |
|---|---|
| 配方发现、单机 FIFO 队列、超时、独立评价、SQLite + 文件存储 | 单服务、无多用户认证，不要直接暴露公网 |
| 回合内核、插件契约、conformance、干净统计量 | 契约缺口 R1–R7 仍在，见学习路径 |
| 内置插件：图像扰动、目标移动、若干监控、两个教学示例 | `native/plugins/recipes.json`；不是研究卡 |
| 危险谓词 `workspace_exit` / `object_drop` / `fast_contact` | 阈值按干净基线标定过一轮；成功率不能代替安全率 |
| 红队目录、实验草稿、对照臂、报告和矩阵 API + 四页工作台 | 编排已有插件，不产生新的攻击或防御算法 |
| TD-MPC2 PushCube：102,400 步、干净基线 50/50 | 单训练种子的工程基线 |
| MemoryVLA Bridge 四任务平均 72.9（官方 71.9） | 已接回合内核，探针只有 state |
| OpenVLA、小型状态 WM、Dreamer、RLVR、Wan、ModelScope、RENEW、EmbodiedJev | 各自有原生入口和有限验证；多数不能挂 S2–S4 |
