# EmbodiedJev 过程对比页

入口：<http://127.0.0.1:8765/#embodied>。也可以从平台左侧选择 **过程对比**。

这个页面将两路或三路机械臂实验并排展示，用来查看不同决策方法在同一任务中选择了什么、机械臂如何执行，以及最终发生了什么。当前支持 EmbodiedJev 的 MuJoCo Panda 任务：**搬运入盘（transfer）**、**方块堆叠（stack）**、**越障搬运（barrier）**。

## 选择历史实验

1. 打开 **历史实验**，选择 **2 路**或 **3 路**。
2. 分别为通道 A、B、C 选择实验。列表包含规则基线、Chat、JEV 的原始实验，不包含独立评价任务和回放缓存准备任务。
3. 如果某一路显示“此历史回合尚未生成交互场景”，点击该路的 **准备 3D 回放**。准备任务会进入平台队列，完成后页面自动加载。
4. 等所需回放就绪后，使用 **同步回放** 查看动作过程。

历史对比可以选择不同任务或不同参数的实验；页面会提示任务、种子、场景哈希、控制模式、观测模式、预演开关或决策阈值的差异及缺失。出现这些提示时，不能将展示结果直接解释为相同条件下的模型优劣。

## 新建两路或三路对比

切换到 **新建对比**，指定任务、随机种子，并为每个通道选择 **规则基线**、**Chat 模型**或 **JEV 模型**。展开 **共同执行参数** 可以设置：

| 参数 | 用途 |
| --- | --- |
| 控制模式 | 技能动作、增量控制或分层控制 |
| 观测模式 | 结构化仿真状态或 RGB-D 感知 |
| 决策阈值 | 对提供候选概率的决策应用阈值；不能据此假定没有概率的 Chat 决策获得相同置信度保障 |
| 最多动作周期 | 每一路独立的动作预算 |
| 每路 API 调用上限 | 每个远程模型实验的请求预算；规则基线不调用模型 API |
| 动作预演 | 开启上游提供的仿真候选检查 |

点击 **开始对比（逐路排队）** 后，每一路会成为独立的平台实验。它们共用上述任务、种子和执行参数，按照平台队列逐路运行。页面并排展示不表示模型请求并发执行。

Chat 和 JEV 使用后台已经配置的连接；新建实验会产生相应的模型调用。此页面不输入或展示 API 密钥。模型请求采用串行处理，没有额外固定两秒间隔；遇到限流时按后台有上限的重试配置处理。

如果提交到一半发生错误，页面会说明已经创建了多少路实验。已经创建的实验仍然存在，可查看详情或停止，不能把这次提交视为全部失败后直接重复全部通道。

## 实时进程与同步回放

| 模式 | 展示内容 | 时间含义 |
| --- | --- | --- |
| **实时进程** | 运行中最近收到的场景、状态、候选和决策快照；已经完成的通道显示末帧 | 快照定期更新，排队中的各路不按墙钟时间同步 |
| **同步回放** | 保存的完整姿态序列及关联动作记录 | 各路以自己的第一帧为零点，按相对仿真时间同步 |

同步回放支持播放、暂停、拖动时间条、回到起点、上一个动作、下一个动作，以及 **0.5× / 1× / 2×** 倍速。动作时间线中的周期按钮可以跳到该动作段的首个记录帧。

各路使用真实保存的姿态帧。时间光标落在两帧之间时，展示光标之前最近的记录帧，不生成中间姿态。较短的回合到达末尾后保持末帧，其他通道继续播放。相对仿真时间对齐不会消除不同动作时长的差异，也不代表各路处于同一个决策周期。

**暂停回放只暂停观看。** 如需停止真实运行，使用 **停止所选实验**；已完成的通道不会重新执行。停止会保留已经归档的证据，但尚在执行的动作可能没有完整的动作结果记录。

模型等待时间不等于物理运动时间。页面的 **墙钟耗时** 和单次 **请求耗时** 用于查看运行及接口时间；回放时间条用于查看仿真动作过程。

## 旋转场景与查看逐步证据

三维画面使用原仿真场景的机器人网格和几何位姿。自由视角支持拖动旋转、右键平移、滚轮缩放；俯视模式固定观察方向并保留平移与缩放。每个场景都有 **复位** 按钮。

顶部的 **全部俯视 / 全部自由视角** 和单个场景的视角模式按钮会统一切换各路模式。自由视角下，各路的手动拖动、缩放和单框复位分别作用于自己的场景。

每个通道还提供以下信息：

- **动作决策或阶段决策**：所选候选、请求耗时、接口实际提供的概率及当前阶段。
- **候选动作与预演**：目标末端位置、夹爪命令、动作时长、检查是否通过，以及已有的拒绝原因或预演结果。
- **当前仿真状态**：末端 TCP、物体和目标位置，夹爪、持物、支撑接触和配置内禁区接触信号。
- **全回合记录**：模型调用次数、动作记录数量和墙钟耗时。这些是整个回合的数据，不是时间光标所在帧的数据。
- **完整动作、输入与事件**：展开归档的动作历史、决策输入和事件；这里展示全回合证据，不随时间光标裁剪。
- **运行详情 / 结果与评价 / 姿态回放视频 / 回合 JSON**：跳转到已有实验记录、独立评价或相应产物。

当前仿真状态与实际模型输入应分开阅读。例如 RGB-D 模式中的模型输入经过感知处理；三维场景和仿真位置读数不能证明模型直接看到了这些精确状态。实际发送给模型的内容应以决策输入记录为准。

动作决策按已记录的动作段关联。未保存精确请求时刻时，页面会明确标注，不能据此推断逐请求的精确时间线。回放尚未到达该动作记录的完成时刻时，不提前显示该动作完成后的状态。

## 如何理解概率与结束状态

- **候选概率不是任务成功概率，也不是风险概率。** 页面保留接口报告的数值和实际选中项，不重新归一化或将最大概率候选替换成模型选择。
- Chat 决策没有提供候选概率时，显示 **该决策未提供候选概率**。缺失表示未知，不能填成零，也不能与 JEV 的候选概率直接作数值排名。
- 分层控制可能记录多个通道的独立决策；页面不会将它们拼成未经模型提供的联合概率。
- JEV 低于阈值而停止时，可能在末帧保留一项尚未执行的决策。页面将其标记为末帧的未执行决策，并说明请求时刻未记录；不能把它算作已完成动作。
- 平台运行状态 **completed** 表示实验流程已经结束并保存结果；是否完成机械臂任务，要看 **任务成功** 和原始回合状态。置信度不足、动作预算耗尽或停滞不能算作任务成功。
- 禁区接触读数仅覆盖当前上游实现配置的接触检查；未观察到此信号不等于获得全面安全保证。候选预演检查未通过，也不等于真实执行已经发生碰撞。

## 历史 3D 缓存和导出

历史回放准备读取原始 `episode.raw.json` 中保存的 `qpos`、仿真时间及目标变化，验证场景和源码来源后，仅用 MuJoCo 的 **`mj_forward`** 还原几何位姿。

准备过程不调用策略或模型 API，不调用 `mj_step` 推进新物理过程，也不重写原始实验。历史交互缓存保存在当前平台数据目录的 `visual-cache/<run_id>/`，通过原始文件哈希及缓存清单检查来源一致性。源码版本、原始记录或缓存不匹配时，应恢复对应的原始版本或重新准备缓存；不能把不匹配的场景当作原实验继续展示。

**导出对比清单** 会下载 `process-comparison.json`，包含所选运行 ID、当前光标、时间对齐方式及已加载的对照条件。该清单用于记录这次查看组合，不包含全部轨迹、录像或密钥；完整证据仍保存在各原始运行中。

## 常见显示问题

| 情况 | 处理方式 |
| --- | --- |
| 等待场景数据或轨迹帧 | 确認是否已选择实验、实验是否仍排队，以及历史回放是否需要准备 |
| 3D 回放正在准备 | 等待平台队列完成准备任务；此过程无需再次调用模型 |
| WebGL 无法创建或上下文丢失 | 点击重新加载场景，检查浏览器图形加速；仍不可用时打开该回合的姿态回放视频 |
| 原始记录或来源信息缺失 | 查看运行详情和已归档文件；缺少必要记录时无法可信地补出三维轨迹 |
| 对比条件提示不一致 | 选择条件一致的历史回合，或通过新建对比使用共同参数重跑 |

## 实现位置

- `web/src/pages/EmbodiedComparison.tsx`：历史选择、新建对比、实时快照、同步回放和证据面板。
- `web/src/embodied.ts`：帧定位、动作关联、未知概率处理和对照条件检查。
- `web/src/components/EmbodiedScene.tsx`、`robot-scene.ts`：React 场景生命周期及 Three.js 真实网格绘制。
- `src/wms/app/embodied_visual.py`：可视化状态、素材读取和历史准备接口。
- `src/wms/engines/embodied_jev/visualization.py`：实时快照、已记录姿态重建、缓存来源清单。

验收结果应以本次保存的测试、浏览器检查及原始实验记录为准。本说明不将功能接线验收表述为模型性能基准。
