# 视觉机械臂鲁棒性实验的现有能力与接入建议

核对日期：2026 年 10 月 14 日。需求：现成抓取或放置任务，测试短暂遮挡、模糊、目标位置变化，重点分析时序感知和目标状态估计。

结论：平台已有可复用的任务执行、状态控制、录像和轨迹基础，但尚未交付这一需求所需的完整视觉抓放闭环。视觉能力现在是明确需求，应进入近期交付；不能只把遮挡/模糊加在录像上，继续用真实物体状态控制机器人。

## 3 图像干预 目标移动和日志

| 需求 | 当前程度 | 需要补充 |
| --- | --- | --- |
| 修改算法实际接收的图像 | OpenVLA 可读取外部处理后的单图；机械臂在线图像扰动尚未统一 | 在真实相机输出到模型预处理之间加入观测包装器 |
| 短暂遮挡与模糊 | 没有经过验收的按时窗注入工具 | 相机、开始/结束时间、遮挡区域/强度、模糊参数、独立随机种子 |
| 时序感知 | 当前 OpenVLA 路径每次只读一张图；状态控制不能代替视觉记忆 | 记录历史时间戳；需要研究显式记忆时增加独立估计/跟踪模块 |
| 回合内物体/目标移动 | ManiSkill 平台接口未实现；JEV 上游已有一次 object_shift/target_shift 代码 | 按具体任务包装并实测，明确目标更新与物理状态同步 |
| 图像、动作、物体状态记录 | 已有轨迹、状态数组和录像；部分已有逐步对齐 | 同时保存原图、模型实际输入、预测/估计、执行动作、评价真值和干预记录 |

JEV 上游位置干预按决策周期触发，支持物体与目标平移；当前平台已归档回合未验证这条干预路径。其 vision/chat/incremental 代码会向决策接口发送图像，RGB-D 分支还有颜色/深度估计及短期状态保留。但视觉模式、干预和图像扰动仍需真实验收；模拟器预演还可能使用特权安全信息，研究中要说明或单独消融。

建议分清两种“目标移动”：一是待抓物体移动，考验物体重新定位；二是放置位置/容器移动，考验任务目标更新。分别设计实验，不用一个位移参数同时改变两者。

图像遮挡或模糊应修改观测，不修改仿真真值。物体移动则会改变真实世界状态，应明确是瞬移还是外力，并处理速度、接触、相机刷新和成功判据。真实遮挡物还可能影响碰撞，不能与像素遮挡混为同一种实验。

## 4 现成视觉基线选择

### 方案 A 优先使用已有训练权重

推荐首先验证 `OpenVLA + LIBERO-Spatial` 中的一项抓取放置任务。官方已发布匹配权重 `openvla/openvla-7b-finetuned-libero-spatial` 和完整闭环评测脚本，不需要为了第一次运行先训练模型。

需要新增的是 LIBERO 原生环境/任务入口，换用该任务匹配的权重，沿用官方图像预处理、动作反归一化、控制器与复位流程；当前已下载的通用 OpenVLA 权重不等于这个微调权重。

先通过官方原生路径验证无扰动回合，再包装为平台配方，随后在图像进入模型的位置加扰动。不能只在当前单图接口外机械地循环调用，也不能把 LIBERO 的动作直接发给现有 ManiSkill 关节控制器。

该官方策略是当前帧到动作的视觉反馈基线。它没有对外的物体位姿估计、历史帧记忆或预测分布接口。因此可用于衡量扰动导致的任务性能下降，不能据动作输出直接声称测到了目标估计误差。需要后者时，另加明确输出估计状态的模块。

官方来源：

- [任务匹配的 OpenVLA 权重](https://huggingface.co/openvla/openvla-7b-finetuned-libero-spatial)
- [官方闭环评测说明](https://github.com/openvla/openvla#launching-libero-evaluations)
- [闭环评测源码](https://github.com/openvla/openvla/blob/main/experiments/robot/libero/run_libero_eval.py)

### 方案 B 保持 ManiSkill 并研究状态估计机制

从 `PickCube-v1` 单任务开始，先采用官方规划/状态策略验证相机、位姿干预和日志，再使用真正读取图像的策略或“视觉状态估计器 + 固定控制器”。规划器或状态策略属于机制检查/参考上限，不用于宣称遮挡鲁棒性。

官方提供 RGB PPO 与 RGB 模仿学习训练路径，但本轮未核实 ManiSkill3 PickCube/StackCube 的可直接下载 RGB 策略权重。官方演示目录中能找到的相关 PPO 权重对应状态策略，不能混写成现成视觉策略。该路线要预留视觉策略训练或另找匹配权重的工作。

默认 RGB 观测也不自动保证没有目标真值输入。例如当前官方 PickCube 的额外字段包含目标坐标、TCP 位姿和抓取标记，目标球还被隐藏于传感器画面。若研究的是视觉目标定位，必须检查模型究竟读取哪些字段，以及目标是否真的在图像中可观测。

已知任务指令/目标坐标可以在明确的问题定义中作为合法输入；但不能把依靠这些真值字段完成的行为，解释为从图像估计了被遮挡目标。可以允许真实可获得的关节/末端本体感知，同时把物体状态真值留给评价器。

官方来源：

- [ManiSkill 抓取与堆叠任务](https://maniskill.readthedocs.io/en/latest/tasks/table_top_gripper/index.html)
- [RGB PPO 训练与评测说明](https://github.com/mani-skill/ManiSkill/blob/main/examples/baselines/ppo/README.md)
- [PickCube 观测及目标可见性实现](https://github.com/mani-skill/ManiSkill/blob/main/mani_skill/envs/tasks/tabletop/pick_cube.py)
- [官方状态 PPO 演示生成脚本](https://github.com/mani-skill/ManiSkill/blob/main/scripts/data_generation/rl.sh)

## 5 针对实际需求调整近期交付

先做一个真实视觉任务的完整纵向流程，不同时扩展多个抓放任务、模型和网页功能。基础共享资源与工作区工作可以并行，但不应等待整个子平台建设完才验证研究可行性。

1. 选定一个任务匹配的视觉权重，验证原生无扰动闭环并保存参考结果。优先走方案 A；若必须使用 ManiSkill，按方案 B 安排训练/估计器工作。
2. 接入公共观察/动作接口，记录模型实际输入，保证评价真值不会流入需要视觉估计的控制链路。
3. 分别实现无扰动、短暂遮挡、模糊、位置变化四组实验；先单因素，再做遮挡期间移动等组合条件。
4. 按相同初始条件、任务和种子配对比较成功率、最终误差、动作变化与扰动后恢复时间。若模型输出目标估计，再增加位置误差及遮挡期间误差增长。
5. 包装成子平台可调用配方，保留自定义任务函数；新增成员先复现实验，再修改自己的算法。

时序实验还应记录仿真时间、控制步、策略决策步及推理墙钟时间。不同策略动作分块或决策频率不同，不能直接按相同“第 20 步”视作相同干预时长。遮挡期内可否使用深度、历史观测、接触信息和模拟器预演，应在协议中明示。

建议最小日志：`episode_id/step/sim_time`、干净图像引用、受扰图像引用、实际模型输入引用、建议/执行动作、物体/TCP/目标真值、可选估计状态、奖励/终止、干预参数及来源版本。MP4 用来查看，逐步数组与元数据用于计算指标。

因此调整之前的优先级：保留 TD-MPC2 作为平台状态控制回归基线，但近期研究基线改成真正的视觉抓放组合；状态 WM 单独 predict、更多任务与完整网页可以按研究依赖安排，不应挤占视觉闭环的验证工作。
